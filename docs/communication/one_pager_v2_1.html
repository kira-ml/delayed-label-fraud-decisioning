The question I should have asked first

V2 tested whether the result survives harder conditions. It did not test whether the comparison was fair. This update does: the V1 baseline was a 50% cut-off, and at a 1.1% fraud rate, that is barely better than approve-all. The 57.91% was mostly threshold placement.

What this does not prove

  • Not a production estimate. BAF is synthetic.
  • Not a generalization claim. One dataset, one cost matrix, one split.
  • Not a causal claim. The policy is evaluated, not deployed.
  • The 2-month delay result uses a separate split, so it is not a like-for-like comparison.
  • Not a fairness claim. Block-rate disparity was tested; review-rate disparity was larger and is not pre-registered.
  • Amount is a proxy: proposed_credit_limit.

What changed since the V2 post

  • Headline: 57.91% → 22.29% vs a fair cost-optimal baseline.
  • New baseline: a strong simple baseline tuned on validation.
  • New report: reports/ablation.md with the waterfall.
  • New tests: 76 unit and integration tests; the pipeline is unchanged.

What did not change

  • The six V2 verdicts: 3 survived, 1 fragile, 2 killed.
  • The model, cost matrix, chronological split, and policy.
  • The censored-row handling and the excluded month 7.
  • The limitations: synthetic data, one regime, amount proxy.
The lesson. Robustness testing is not only "does it survive harder conditions?" It is also "is the comparison fair?" I stress-tested the first four weeks ago and missed the second. The corrected number is smaller, and it is the one I can defend.

**What changed:**

- Collapsed `src/pipeline.py` to a single step list

**Evidence of the fix:** every report now shows policy cost/txn = 0.007491.
Before, `evaluate_compare` printed 0.007491 (LR) while `backtest.py`
printed numbers from the LightGBM booster.

**Decision:** one pipeline. One classifier. One backtest.

### E2 — Noise-band guard on classifier selection

**Why:** the pre-registered rule in `evaluation_protocol.md` §17.1 requires
that a CV selection only counts as a *finding* if the top classifier wins
every fold AND the gap to the runner-up exceeds 5% relative. Without this
guard, any 0.1% CV margin would flip the selection arbitrarily.

**What was measured:**

| Classifier | CV realized cost (mean ± SD) |
|---|---|
| lightgbm | 0.005852 ± 0.000300 |
| logistic_regression | 0.005915 ± 0.000338 |
| random_forest | 0.006515 ± 0.000579 |

- Per-fold winners: `['lightgbm', 'lightgbm']` (consistent)
- Top gap: 0.000063 → **1.07% relative**
- Threshold: 5%

**Result:** 1.07% < 5% → **non-finding**. Tie broken by simplicity order
(LR > RF > LGBM), per `evaluation_protocol.md` §8.

**Decision:** LogisticRegression selected.

**Honest cost of the rule:** LGBM's test cost was ~0.007332 on the same
window; LR's is 0.007491 — a 2.2% higher cost. The pre-registered rule
forbids selecting on that 1.07% margin. The claim that is defensible is
"we applied the guard; the margin was inside noise; we selected by
simplicity." Selecting LGBM on a 1% CV edge would be the weaker claim.

### E4 — Calibration gate

**Why:** the decision policy assumes `p_fraud` is a real probability. An
uncalibrated score produces wrong expected costs and wrong actions.

**Rule:** ECE (10 quantile bins) < 0.05 on the validation window.

**Result:**

| Metric | Value |
|---|---|
| ECE | 0.0033 |
| Brier (model) | 0.009444 |
| Brier (trivial) | 0.010103 |
| Brier gain over trivial | 6.52% |

**Decision:** gate passed. No calibration step applied. Raw LR output is
used directly by the policy.

**Note:** the reliability table shows mild overconfidence in the top
decile (bin 9: mean predicted 8.29%, actual 6.83%). Those scores land in
the review band, not at the block boundary, so the mispricing does not
flip any decision. Documented, not corrected — no measured failure
justifies a correction.

### E5 — Bootstrap confidence interval on the policy advantage

**Why:** `evaluation_protocol.md` §13.1 requires a 95% bootstrap CI on the
test window. A finding requires the CI to exclude zero.

**Rule:** 1,000 resamples, seed 42.

**Result:**

| Quantity | Point | 95% CI |
|---|---:|---|
| Policy cost/txn | 0.007491 | [0.007196, 0.007797] |
| Baseline cost/txn | 0.018737 | [0.017902, 0.019590] |
| Difference (baseline − policy) | 0.011246 | [0.010493, 0.012021] |
| Advantage | 60.02% | [56.00%, 64.16%] |

**Decision:** CI excludes zero → the policy advantage is a **finding**.
The advantage is well above the 5% minimum effect size from §13.2.

### E7 — Feature importance aggregation for linear models

**Why:** LogisticRegression's `coef_` has one entry per expanded feature.
The saved preprocessor one-hot expands 5 categorical columns into ~25
columns, so `coef_` has ~48 entries while the feature list has 28.
`models/feature_importances.json` ended up with mismatched array lengths,
and the Streamlit sidebar crashed with `ValueError: All arrays must be of
the same length` when it tried to build a DataFrame.

**Fix:** aggregate one-hot coefficients back to their original feature
names before saving.

- `num__<feat>` → coefficient added to `<feat>`
- `cat__<feat>_<value>` → coefficient added to `<feat>`
- Save only if `len(importances) == len(features)`; otherwise remove the
  stale file so the app skips the panel

**Result:** `models/feature_importances.json` now has 28 features and 28
importances. Top-5 by magnitude: `source`, `keep_alive_session`,
`session_length_in_minutes`, `phone_home_valid`, `credit_risk_score`.

**Decision:** aggregated importances are the correct representation for
linear models behind a one-hot preprocessor. Tree models are unaffected
because their preprocessors do not expand columns.

**Defensive guard added:** the app checks that `features` and
`importances` lengths match before rendering the bar chart. A corrupt
artifact can no longer crash the page.

## Guiding Rule (restated for tomorrow)

> The pipeline is a decision pipeline. The classifier is an input to the
> policy. The policy is the product. The backtest is the evidence.

> The test window is used once. No exceptions.

> A claim is only a finding if the bootstrap CI on the cost advantage
> excludes zero and the relative reduction exceeds 5%. Everything else is
> a non-finding, reported as such.

### E1 — T1: Centralized `realized_cost` and `choose_actions`

**Why:** Three independent implementations of `realized_cost` existed
(`backtest.py`, `bootstrap.py`, `sensitivity.py`) and two independent
implementations of the argmin policy existed (`decide.choose_actions` vs.
local copies in `bootstrap.py` and `sensitivity.py`). A fix in one would
not propagate.

**Evidence:**

```

src/policy/decide.py:def choose_actions(...)
src/evaluation/bootstrap.py:def policy_actions(...)
src/evaluation/sensitivity.py:def policy_actions(...)
```

Five duplicate implementations of two critical functions.

**What:** Kept `decide.choose_actions` as the single argmin rule and
`backtest.realized_cost` as the single cost function. Removed local copies
in `bootstrap.py` and `sensitivity.py`; both now import from canonical
locations. Action encoding was unified on string actions
(`"approve"/"review"/"block"`) across all three modules.

**Decision:** adopted. Re-ran the pipeline; all numbers identical to the
2026-09-25 run before the change.

### E2 — T2: Made `bootstrap.py` verify the strongest baseline

**Why:** `bootstrap.py` hardcoded `static_actions(p)` (selected classifier
+ 0.5) as the comparison baseline. The protocol requires comparison against
the **strongest** canonical baseline. The code did not verify that the
selected classifier's +0.5 was in fact the strongest. It was a false
barbell — looked like a strongest-baseline comparison but never checked.

**Evidence:**

```python
# before
bas_actions = static_actions(p)  # assumes LR+0.5 is strongest
```

No code path in `bootstrap.py` computed RF+0.5 or LGBM+0.5.

**What:** Replaced the hardcoded baseline with a dict of all canonical
baselines and used `min(bas_costs, key=...)` to select the strongest. A
second bug surfaced during verification: the newly added `Random` baseline
consumed RNG draws from the same stream as the bootstrap loop, shifting
the CI from `[56.00%, 64.16%]` to `[56.00%, 64.15%]`. Fixed by giving the
baseline's RNG its own seeded generator.

**Evidence (post-fix):**

```
[bootstrap] strongest baseline: Classifier+0.5
[bootstrap] Advantage 95% CI: [56.00%, 64.16%]
[bootstrap] Difference CI excludes zero: True
```

CI restored exactly; still matched the pre-change value on 2026-09-28.

**Decision:** adopted. This is the change that surfaced the eventual
T10/T11 finding (see E13).

### E4 — T4: Made `choose_actions` fail loudly on missing amounts

**Why:** When `costs['amount_scaled'] is True` and `amounts is None`,
`choose_actions` silently fell back to constant `fraud_loss`. The
deployed policy depends on amount scaling; a silent fallback would hide a
real misconfiguration.

**Evidence:**

```python
# before
if costs.get("amount_scaled", False) and amounts is not None:
    ...  # only reached when amounts is present
else:
    fraud_loss = np.full(n, float(costs["fraud_loss"]))
```

A misconfigured caller would get silently wrong decisions with no
diagnostic.

**What:** Added a `raise ValueError` when `amount_scaled=True` but
`amounts is None`. Grepped every caller (`train_compare.py`,
`evaluate_compare.py`, `decide.py::main`, `bootstrap.py`,
`sensitivity.py`) — all pass amounts. No caller relies on the fallback.

**Decision:** adopted. All 58 tests still pass; no behavior change for any
existing caller.

### E13 — T10: Verified strongest baseline empirically

**Why:** T2 (E2) made `bootstrap.py` verify the strongest baseline, but
`backtest.py` still reported only the selected classifier's +0.5 baseline
as "the strongest baseline." The protocol requires comparison against the
strongest of all canonical baselines, not the selected classifier's
baseline. The code and protocol disagreed.

**Evidence:** Wrote a read-only diagnostic (`scripts/check_baselines.py`)
that refit each classifier on the full training window and computed
realized cost for each classifier + static 0.5:

```
=== Static 0.5 baselines on test window ===
  logistic_regression    + 0.5   0.018737
  random_forest          + 0.5   0.018928
  lightgbm               + 0.5   0.017798   <- strongest
  approve-all                    0.018928
  block-all                      0.098742

Strongest classifier + 0.5: lightgbm (0.017798)
Currently reported strongest (LR+0.5): 0.018737
-> CHANGED.
```

**What:** **This was a real finding, not a false alarm.** The strongest
baseline is LGBM+0.5 at `0.017798`, not LR+0.5 at `0.018737`. The
difference is small in absolute terms but changes the reported advantage
from 60.02% to 57.91%.

**Decision:** adopted the finding. Extended `score.py` to score all three
classifiers, and extended `backtest.py`, `bootstrap.py`,
`sensitivity.py` to compare against all three baselines. Re-ran the
pipeline; reports regenerated.

**Note:** The classifier, the policy, the split, and the cost matrix did
not change. Only which pre-registered baseline is correctly identified as
"strongest" changed. The test window was not re-tuned. The protocol
already specified baselines 4–6 (LR / RF / LGBM + 0.5) as part of the
comparison set; the as-built backtest had been omitting two of the three.

## Guiding Rule (restated)

> The pipeline is a decision pipeline. The classifier is an input to the
> policy. The policy is the product. The backtest is the evidence.

> The test window is used once. No exceptions.

> A claim is only a finding if the bootstrap CI on the cost advantage
> excludes zero and the relative reduction exceeds 5%. Everything else is
> a non-finding, reported as such.

> Each addition is justified by a measured result, not by the desire to

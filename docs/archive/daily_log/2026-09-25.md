### E2 — C1: Fixed `select_best()` tiebreak bug

**Why:** `evaluate_compare.py`'s tiebreak loop picked the first algorithm
in `SIMPLICITY_ORDER` regardless of whether it was inside the noise band
of the best classifier. As written, if LR were the worst of the three but
the top two happened to be within 5%, the code would still pick LR.

**Evidence:**
```python
for alg in SIMPLICITY_ORDER:
    if alg in means:
        tiebreak = alg
        break
```

This is not the pre-registered rule in `evaluation_protocol.md` §17.1.

**Fix:** restrict the tiebreak to algorithms whose CV cost is within the
5% band of the best.

**Result:** on the current data, the correct selection is still LR (LR is
second-best, 1.07% behind LGBM, well inside the band). The bug was latent;
the fix eliminates the latent failure mode.

**Decision:** adopted. Pipeline re-run confirms identical selection and
identical numbers.

## Guiding Rule (restated for tomorrow)

> The pipeline is a decision pipeline. The classifier is an input to the
> policy. The policy is the product. The backtest is the evidence.

> The test window is used once. No exceptions.

> A claim is only a finding if the bootstrap CI on the cost advantage
> excludes zero and the relative reduction exceeds 5%. Everything else
> is a non-finding, reported as such.

> Each addition is justified by a measured result, not by the desire to
> build more. If an addition cannot point to a number that made it
> necessary, it does not happen.

> The framework is frozen. The remaining work is to communicate it, not
> to expand it.
